# 出发鸭后端项目说明文档

## 一、项目概述

### 1.1 项目简介
"出发鸭"是一个旅行社交平台的后端服务项目，为用户提供旅行内容分享、活动组织、用户互动等功能。用户可以发布游记、攻略等内容，参与旅行活动，与其他用户互动交流。

### 1.2 技术栈
| 技术 | 版本 | 说明 |
|------|------|------|
| Java | 17 | 编程语言 |
| Spring Boot | 3.2.0 | Web框架 |
| MyBatis | 3.0.3 | ORM框架（数据库操作） |
| MySQL | - | 数据库 |
| Druid | 1.2.20 | 数据库连接池 |
| Lombok | - | 简化代码的工具 |

### 1.3 项目结构
```
let_go_dack_service/
├── src/main/java/com/example/chufaya/
│   ├── config/          # 配置类
│   ├── controller/      # 控制器（接收请求）
│   ├── dto/             # 数据传输对象
│   ├── entity/          # 实体类（对应数据库表）
│   ├── mapper/          # 数据访问层（SQL操作）
│   ├── service/         # 业务逻辑层
│   └── LetGoDackApplication.java  # 启动入口

│   ├── mapper/          # MyBatis XML映射文件
│   └── application.yml  # 配置文件
└── uploads/             # 文件上传目录
```

## 二、后端处理流程详解

### 2.1 整体架构流程
```
用户请求 → Controller（控制器） → Service（业务逻辑） → Mapper（数据库操作） → 数据库
                ↓
           DTO（数据传输对象）
                ↓
           统一响应格式返回给用户
```

### 2.2 详细流程说明

**第一步：用户发起请求**
- 用户通过小程序或浏览器发送HTTP请求（如GET、POST）
- 请求包含URL路径、请求参数、请求体等信息

**第二步：Controller接收请求**
- Controller是"门口保安"，负责接收用户请求
- 它会验证请求参数，调用对应的Service处理业务
- 例如：用户点击"登录"，AuthController接收登录请求

**第三步：Service处理业务逻辑**
- Service是"业务经理"，负责处理具体的业务逻辑
- 它会调用Mapper进行数据库操作，处理数据
- 例如：AuthService检查用户是否存在、验证密码

**第四步：Mapper操作数据库**
- Mapper是"数据库操作员"，负责执行SQL语句
- 它通过MyBatis框架与数据库交互
- 例如：UserMapper查询用户表，获取用户信息

**第五步：返回响应**
- Service处理完成后，将结果返回给Controller
- Controller使用UnifiedResponse统一格式返回给用户
- 响应包含：code（状态码）、message（提示信息）、data（数据）

### 2.3 统一响应格式
所有接口返回的数据格式都是统一的：
```json
{
  "code": 200,        // 状态码：200成功，500失败，404未找到
  "message": "操作成功", // 提示信息
  "data": { ... }     // 具体数据
}
```

## 四、数据库表结构详解

### 4.1 数据库基本信息
- **数据库名称**: let_go_dack
- **字符集**: utf8mb4（支持中文和特殊字符）
- **引擎**: InnoDB（支持事务和外键）

### 4.2 数据库表详解

#### 表1：users（用户表）
**用途**: 存储所有注册用户的基本信息

| 字段名 | 类型 | 说明 | 示例值 |
|--------|------|------|--------|
| user_id | BIGINT | 用户唯一ID（主键，自动生成） | 1, 2, 3 |
| nickname | VARCHAR(50) | 用户昵称 | "旅行达人小王" |
| duck_id | VARCHAR(20) | 用户鸭号（唯一标识） | "duck12345" |
| phone | VARCHAR(20) | 手机号（唯一） | "13812345678" |
| password_hash | VARCHAR(255) | 密码（目前明文存储） | "123456" |
| ip_location | VARCHAR(100) | IP归属地 | "北京" |
| bio | VARCHAR(200) | 个人简介 | "热爱旅行的背包客" |
| avatar_url | VARCHAR(500) | 头像图片地址 | "http://localhost:8080/uploads/xxx.png" |
| follow_count | INT | 关注人数 | 10 |
| fans_count | INT | 粉丝人数 | 50 |
| like_count | INT | 获赞总数 | 100 |
| status | TINYINT | 用户状态（1正常，0禁用） | 1 |
| create_time | DATETIME | 注册时间 | "2024-01-01 10:00:00" |
| update_time | DATETIME | 更新时间 | "2024-01-02 15:30:00" |

**通俗解释**: 这个表就像一个"用户档案柜"，每个用户有一条记录，记录了用户的昵称、手机号、头像、粉丝数等信息。

### 5.1 认证功能（AuthController）

#### 5.1.1 用户注册
**接口地址**: `POST /api/auth/register`

**请求参数**:
```json
{
  "phone": "13812345678",    // 手机号（必填）
  "password": "123456",      // 密码（必填）
```

1. Controller接收手机号、密码、昵称

3. 如果未注册，创建新用户，生成鸭号

## 七、常见问题解答

### Q1: 什么是Controller？
Controller就像"门口保安"，负责接收用户发来的请求，验证参数，然后调用Service处理业务。

### Q2: 什么是Service？
Service就像"业务经理"，负责处理具体的业务逻辑，比如验证密码、计算数据、调用数据库等。

### Q3: 什么是Mapper？
Mapper就像"数据库操作员"，负责执行SQL语句，与数据库交互，查询或保存数据。

### Q4: 什么是DTO？
DTO（Data Transfer Object）就像"快递包裹"，用于前后端数据传输，包含请求参数或返回数据。

### Q5: 什么是Entity？
Entity就像"数据模型"，对应数据库中的一张表，每个字段对应表中的一列。

### Q6: 什么是MyBatis？
MyBatis是一个ORM框架，让我们用Java代码操作数据库，不用手写复杂的SQL语句。

### Q7: 什么是Spring Boot？
Spring Boot是一个Web框架，帮我们快速搭建后端服务，处理HTTP请求和响应。

## 八、项目特点总结

1. **统一响应格式**: 所有接口返回格式统一，便于前端处理
2. **分层架构**: Controller-Service-Mapper三层分离，职责清晰
3. **自动建表**: 项目启动时自动创建数据库表，无需手动执行SQL
4. **跨域支持**: 配置了CORS，允许小程序/前端跨域调用
5. **文件上传**: 支持图片上传，自动生成唯一文件名
6. **分页查询**: 所有列表接口支持分页，避免数据过多
